The 2026-09-14 run closed the last two surfaces the tool had refused, by fixing the tool rather than the files. Two more dialects came out of it: workshop-wall.html wrote its home link as &#8962; Home, which the header matcher did not recognise; the-compound-capstone.html bound its handlers as querySelectorAll(…).forEach(…) with no [].forEach.call wrapper, so they survived the cut and the leftover check refused the file. Both refusals were correct. nowalls.py now matches both dialects, and the cut reproduces byte-for-byte from a pristine copy.

Still walled, outside Confluence — seven surfaces. Three are oversize: choose-your-leader-full.html, choose-your-leader-v6.html, old-problems-at-new-speed.html. Four sit inside the size lane but carry no se-chrome header at all, so the tool has no anchor to cut against: enjambment.html, en195-arcade.html, and — needing a founder ruling before anyone touches them — comfort-kernel.html and comfort-v3.html, where the preference controls may well be the artifact and the standing order freezes the kernel as it stands.

The 2026-09-24 run cut nothing and found out why. The tool was offered every candidate, including the three oversize builds against a working tree, and refused all eight — every refusal correct. The oversize three are not one missing dialect; they are three walls written by hand, one per file. choose-your-leader-v6.html wraps its wall in an IIFE with double-quoted selectors and arrow functions, and that same block also holds the last-updated logic, which is not wall — so it cannot be deleted whole. old-problems-at-new-speed.html names its variables seEyes and sePanel rather than eyes and panel. choose-your-leader-full.html reads as a binary file before the wall is even reached. Teaching the tool all three would mean three special cases inside the one check that has kept this lane honest, on builds of two to three and a half megabytes. They are hand-set work now, not a tooling gap.

The other two are a design question, not a code one. en195-arcade.html and enjambment.html run a second live wall the old inventory never saw — a Comfort button on #comfortTop, proven this run by clicking it in a headless browser and watching the panel open, not by matching a string. Their chrome is a coinbar carrying coins, tokens and sound, with no se-chrome to add Studio and Cabinet to. Building one touches the style block, which the kernel guard refuses by design. One ruling unblocks both: what does the top bar of a coin-op game look like when it has to carry Studio and Cabinet beside the coin count?

One correction to the earlier list: enjambment-skins.html was never walled. It matched the old inventory pattern only on the word “Legibility” in prose — the name of a seat, not a control.
